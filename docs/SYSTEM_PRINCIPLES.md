# Lab-Monitor 实验室智能监控与预警系统技术原理

> **文档说明**：本手册梳理了系统的核心技术模块、工作机制与算法原理。语言通俗易懂，适合项目汇报、方案讲解与内部学习使用。

## 📌 一、 系统总体架构

系统采用 **“多源感知 ➔ ReID 跨摄归一 ➔ 拓扑空间约束 ➔ 智能告警 ➔ 实时指挥大屏”** 的闭环架构：

```
[ 多路摄像头/视频源 ] (RTSP / 本地文件)
         │
         ▼
[ 1. 目标检测与追踪 ] (YOLOv8 + ByteTrack 实时捕获)
         │
         ▼
[ 2. 跨镜头身份提取 ] (OSNet 512维特征 + 3帧多帧缓冲校验)
         │
         ▼
[ 3. 空间与安全判断 ] 
   ├─► ROI 电子围栏入侵校验 (脚下点多边形在界测试)
   └─► 拓扑穿越与时间校准 (Z-Score AI 自适应学习)
         │
         ▼
[ 4. 告警分级与广播 ] (WARNING 预预警 / ALERT 正式告警 / WebSocket 推送)
         │
         ▼
[ 5. 可视化指挥大屏 ] (HTML5 Canvas 交互 / 矢量拓扑图 / 动态日志)
```

## 🎯 二、 核心技术模块与工作原理

### 1. 目标检测与单镜头追踪 (Person Detection & Tracking)
- **使用的技术**：**YOLOv8 (yolov8n.pt)** + **ByteTrack 算法**。
- **基本原理**：
  - **检测**：YOLOv8 算法每帧扫描画面，精准提取出人体的位置边界框 (BBox)。
  - **追踪**：利用卡尔曼滤波 (Kalman Filter) 预测人员下一帧的位置，配合匈牙利算法做运动匹配，为单镜头内的人员分配连续的轨迹 ID (`Track_ID`)。

---

### 2. ReID 跨镜头身份归一化 (Cross-Camera Person Re-ID)
- **解决的痛点**：同一个人在镜头 A 叫 `Track_01`，走到镜头 B 变成 `Track_05`，系统如何识别为“同一个人”？
- **使用的技术**：**OSNet-x0.25 深度网络** (512维向量) + **多帧缓冲与查重锁**。
- **基本原理**：
  1. **特征提取**：抠出目标人体图像，由 OSNet 神经网络提炼出一个 512 维的数学特征向量（如同人的“视觉指纹”）。
  2. **多帧确认**：防误判机制，连续 3 帧提取的特征一致时，才正式认定为同一身份。
  3. **查重与注册**：在全局身份库 (`IdentityStore`) 锁内做余弦相似度匹配（阈值 0.75）。已有匹配归为老身份 `Global_ID`；无匹配则注册新 `Global_ID`。

---

### 3. ROI 电子围栏与框点入侵检测 (Danger Zone Detection)
- **解决的痛点**：机房服务器重地、高压电柜等危险区域，未经许可不得踏入。
- **使用的技术**：**射线交叉法 / 点在多边形内测试 (`cv2.pointPolygonTest`)**。
- **基本原理**：
  1. **坐标归一化**：前端支持鼠标在监控画面上手动打点绘制多边形，坐标归一化为 `(0.0 ~ 1.0)` 比例存储，不受分辨率影响。
  2. **脚下点检测**：算法不看头和身体，专门计算人体框底边中心点 `(Foot_X, Foot_Y)`（即脚踩的位置）。
  3. **越界判定**：计算脚下点是否落在多边形内部（距离 $\ge 0$），一旦脚踩入围栏，瞬间触发 **🚨 INTRUSION 越界闯入告警**。

---

### 4. 拓扑结构与 AI 通行时间校准 (Topology & AI Calibration)
- **解决的痛点**：如何判断一个人是在正常走动，还是在迷路、滞留或跳跃越界？
- **使用的技术**：**有向拓扑图** + **正态分布 Z-Score 自动修正**。
- **基本原理**：
  - **拓扑有向边**：在 `config/topology.json` 中配置相机间的连通关系（如 `cam_01 ➔ cam_02` 基础预计用时 30s）。
  - **AI 动态学习**：
    - 当人员离开 `cam_01` 时记下时间 $T_1$；在 `cam_02` 出现时记下时间 $T_2$；实际耗时 $\Delta T = T_2 - T_1$。
    - 通行校准器 (`TransitCalibrator`) 记录最近 200 次通行耗时，计算平均用时 $\mu$ 和标准差 $\sigma$。
    - 当数据 $\ge 5$ 条后，AI 学习到的真实平均耗时自动覆盖静态配置，并按正态分布设防：
      $$\text{最大容忍时间} = \mu + \max(1.65\sigma, 5.0\text{s})$$

---

### 5. 可疑行为判定与两阶段告警 (Two-Stage Alert Pipeline)
为了避免过于频繁打扰管理员，系统设计了**两阶段阶梯式响应**：

| 阶段 | 触发条件 | 响应动作 | 业务含义 |
| :--- | :--- | :--- | :--- |
| **Stage 1: WARNING** | 耗时达到最晚 deadline 的 **70%** | 控制台预警 + WebSocket 推送紫色标志 | **预预警**：人员可能滞留，提醒关注 |
| **Stage 2: ALERT** | 超过最晚 deadline 或 闯入 ROI | 全量红框告警 + 蜂鸣音效 + 外部邮件通知 | **正式告警**：发生明确异常，需人工排查 |

---

### 6. RTSP 断流保护与高可用 (RTSP Resiliency)
- **机制**：采用**无限重连 + 指数退避策略**（重连延迟从 3.0s 逐步增长至 60s），有效抵御局域网网络抖动或摄像头临时重启，保证系统 7×24 小时稳定运行不崩溃。
