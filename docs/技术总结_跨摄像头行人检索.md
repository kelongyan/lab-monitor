# 跨摄像头行人检索技术总结
---

## 1. 能力结论

**本系统已实现跨摄像头同一行人检索，并已完成端到端验证。**

实现路径为：为每名行人分配一个与相机无关的全局身份标识（`global_id`），通过外观特征在全局身份底库中完成跨相机身份归一；检索时以该标识聚合全部相机上的轨迹片段，返回命中的视频资产与视频内时间位置。

实测指标：164 个身份中有 **76 个（46.3%）跨越 2 路及以上相机**；单次检索可正确返回同一行人在多路相机中的片段（详见 §6）。

**当前主要技术瓶颈不在"是否支持跨相机"，而在"同一行人的归一稳定性"**（详见 §7）。

---

## 2. 系统构成

| 组件 | 实现 |
|---|---|
| 检测 | YOLOv8n |
| 跟踪 | ByteTrack |
| 外观特征提取 | OSNet-x0.25（Market-1501 度量学习权重），512 维 |
| 身份判定 | 余弦相似度阈值 + Ratio Test |
| 身份底库 | 全局 `IdentityStore`（内存 + SQLite 持久化） |
| 视频资产索引 | `video_assets` 表，记录实测帧数、时长、低清转码产物 |
| 检索接口 | `GET /api/search/person`、`POST /api/search/by-image` |

系统规模：22 路视频源，素材实解码合计 67,576 帧（约 45 分钟），循环播放。

---

## 3. 处理流程

1. **单路处理**：各相机独立执行检测与跟踪，对每条轨迹提取 512 维外观特征。
2. **特征规范化**：对特征进行多帧平均，并减去全局公共分量后重新 L2 归一化。
3. **跨相机比对**：将规范化后的特征与全局身份底库比对，命中则复用已有全局标识，未命中则注册新标识。
4. **轨迹记录**：每条轨迹记录 `(全局标识, 相机编号, 墙钟时间, 视频内时间)` 四元信息。
5. **检索聚合**：按全局标识聚合各相机轨迹，执行停留段切分与循环折叠，关联至具体视频资产。

## 4. 关键技术实现

### 4.1 公共分量中心化（核心技术点）

**问题**：OSNet 输出的单位特征与一个全局方向高度共线。实测全体特征均值向量的范数为 0.80~0.88，而随机方向的期望值约为 0.1。该分量对区分个体无贡献，但使任意两名行人的余弦相似度虚高至 0.98 量级。

**方案**：在匹配路径上引入中心化——以全体已注册特征（主特征与特征库）的均值向量作为中心，查询特征与底库特征均减去该中心后重新归一化。

**效果**：

| 指标 | 中心化前 | 中心化后 |
|---|---|---|
| 异人特征越过阈值的比例 | 54.9% | **1.7%** |
| 跨身份余弦相似度中位数 | +0.50 | −0.13 |

**工程约束**：底库与查询向量必须使用同一中心，否则两者不在同一坐标系，相似度计算结果无效且不会产生任何报错。为此系统将"已中心化的底库"与"所用中心"封装为不可分割的 `MatchContext` 对象原子返回，调用方须通过 `context.prepare()` 变换查询向量。此外设置冷启动护栏：有效特征数少于 8 个或中心范数低于 0.35 时不启用中心化，行为与此前一致。

### 4.2 身份判定准则

判定为同一行人须同时满足以下条件：

1. 余弦相似度 ≥ **0.68**（阈值由标注集标定，见 §5）
2. Ratio Test：次优身份相似度 ÷ 最优身份相似度 ≤ **0.85**，否则判为"歧义"并拒绝匹配

相似度按身份去重后取最大值（同一身份包含主特征与多个姿态特征）。Ratio Test 的设计取向为：**遇歧义时新建身份，而非合并**。

### 4.3 多帧确认机制

单帧特征噪声较大，系统采用两级时序约束：

- **特征缓冲**：每条轨迹维护 8 帧特征缓冲区，以缓冲区均值参与匹配
- **连续确认**：须连续 3 帧匹配到同一身份方可确认；候选身份发生变化或未匹配时，计数清零重新累积

身份一经确认即在轨迹生命周期内锁定，不再变更。

### 4.4 异常可观测性

当出现"查询特征与已有身份相似度 ≥ 0.999 却被判为歧义"的情形时，系统判定为特征空间异常，记录 ERROR 级日志并累加 `collapse_warnings` 计数，经 `/api/metrics/reid` 与 `/api/system/metrics` 对外暴露。该机制使特征塌缩类故障不再静默。

### 4.5 检索与回放

- **双时间轴**：墙钟时间用于跨相机排序，视频内时间用于回放定位。素材循环播放会使墙钟时间跨度远大于实际视频时长，两者不可混用。
- **循环折叠**：素材循环播放导致同一段画面被反复记录（单身份累计轨迹可达 13 万条）。检索结果对循环周期进行检测与折叠，并返回 `loop_factor` 标注压缩倍数，避免产生"出现数万次"的失实呈现。
- **回放资产归一**：同一相机存在原片与低清转码产物两条资产记录。检索结果统一归一到低清片（单路最大约 4.4 MB，原片最大约 183 MB），使回放路径实际受益于分辨率压缩。
- **坐标完整性**：当前 1,338,889 条轨迹中 99.87% 携带视频内时间坐标，检索结果可精确定位至秒。

---

### 4.6 轨迹抖动合并（视图组）

循环折叠（§4.5）解决的是"同一段像素被反复播放"，但折叠后仍残留另一种噪声：**两路相机在同一时间窗内交替确认同一身份**。实测某 3 相机身份折叠后仍有 125 次相机切换，形态为：一路相机完成 132.7 秒长停留后，两路相机在约 8 秒窗口内每 0.2~0.5 秒交替写入一段（段时长几乎全为 0）。成因是两路走廊相机的画面被并行处理。

若直接按时间序列连线，会得到一条在两相机之间反复横跳的折线，**既不表达路线，也会引出"轨迹为何来回跳"的质疑**。

处理方式为"视图组"：把连续时间窗内可见到的相机集合作为一个展示单元，语义对数据如实——"该时段内在两路相机交替可见"。合并规则三条：

1. 短段夹在相同相机集合之间（A-B-A）→ 合并为一个多视角组；**若前一组是真实长停留则不吸收它**，否则会得出"他在 B 相机也停留了 133 秒"的错误结论
2. 短段的相机集合已属于前一组 → 吸收（首条规则合并后残留段与后续组的集合不再相等，不补这条则长交替链会在中途停下）
3. 相机集合相同的相邻组 → 合并

真实前后相继（A 段结束后进入 B 段、无反复）不受影响。实测效果：某身份 21 段 → 4 个视图组、另一身份 120 段 → 14 个视图组。

### 4.7 跨相机抓拍证据

系统提供 `GET /api/identities/{gid}/snapshots`，返回该身份在各路相机上的**真实抓拍**（从低清素材按视频内秒数解码并裁出人体框），并生成带相机名称的横向对比图。图像不含任何合成成分，且素材本身烧录了相机名与时间，可直接作为证据使用。

- **选样**：按框面积、是否贴画面边缘、竖长比三项偏好逐相机挑选代表帧
- **逐相机排序**（而非全局取最大框）：否则远距离机位的小框会被大框相机挤掉，表现为"跨 4 路的身份只出 2 路图"
- **缓存**：裁图与拼图落盘并带元数据侧车文件，重复请求不重新解码
- **视点提示**：`rnd_21`/`rnd_22` 与 `reg_06`/`rnd_07` 的相机描述完全相同（同一视点），应答中一并返回描述供前端提示，避免"跨 4 路相机"被误读为覆盖 4 个位置

## 5. 精度指标与标定方法

### 5.1 标定方法

标注集由两条运动学约束自动生成，未使用人工标注：

- **正样本**：同相机相邻采样帧（间隔 0.4 秒）中 IoU ≥ 0.25 的检测框对
- **负样本**：同相机同一帧中 IoU ≤ 0.05 的检测框对，以及时间区间重叠的不同轨迹簇

规模：正样本 180 对，负样本 232 对。阈值在误报率不超过 5% 的约束下取 F1 最大值。

### 5.2 标定结果（Market-1501 权重，阈值 0.68）

| 指标 | 数值 |
|---|---|
| 精确率 | **91.3%** |
| 召回率 | **63.9%** |
| 误报率 | **4.7%** |
| F1 | 0.752 |

对照：MSMT17 权重在同阈值下精确率 89.9%、召回率 54.4%、F1 0.678，故选用 Market-1501。

### 5.3 召回率受限的成因

中心化后的相似度分布为：同人对中位数 **0.750**（p5 = −0.171），异人对中位数 **0.244**、p95 = **0.671**。阈值 0.68 位于异人 p95 与同人中位数之间的窄区间内，可调余量仅 0.009。

因此阈值设定为**偏保守**：以牺牲召回率换取低误报率。该取向的工程依据是——漏配一名行人的代价远低于将两名不同行人误判为同一人。

## 7. 当前技术局限

### 7.1 同一行人归一稳定性不足（主要瓶颈）

> 注：服务持续运行期间底库仍在增长，本节各项实测的身份总数在 164~166 之间浮动，不影响结论。

当前身份底库存在两个方向上的错误：

1. **欠归并**：164 个身份中，62 个（37.8%）分布于 9 个特征字节完全相同的重复组，最大一组包含 34 个身份。表明同一名行人被多次重复注册，将导致检索结果不完整。
2. **过归并**：存在 1 个身份跨越全部 22 路相机，但仅累计 4,012 条轨迹（对照正常跨 3 路身份为 138,861 条），属被污染的吸收型标识，不可采信。

**成因分析**：主特征采用指数滑动平均，而入镜目标质量偏低（平均特征质量 0.2639），单次观测权重仅为 3%~6%，导致主特征严重滞后于行人的实际外观。同一行人再次入镜时，其新特征与已漂移的存储特征相似度低于阈值，触发重复注册（`created_near_miss` 计数已达 119 次）。身份底库膨胀后，Ratio Test 的歧义判定大幅增加（当前在线匹配率 26.0%，歧义拦截占比 68.7%），进一步加剧上述循环。

身份底库验收数据（中心化口径）：

| 分组 | 对数 | 相似度中位数 | 越过阈值比例 |
|---|---|---|---|
| 同相机 | 6,314 | 1.000 | 95.90% |
| 跨相机 | 7,052 | 0.455 | 16.87% |
| 全体 | 13,366 | 1.000 | 54.20% |

**重复注册的空间分布**：9 个重复组**全部是单路相机内部**的重复（`rnd_04` 占 8 组、`reg_02` 1 组、`rnd_06` 1 组），`rnd_04` 一路即占 113/165 个身份；该相机源片仅 **20.04 秒**、循环播放，是批量重复注册的直接来源。重复组仅涉及 6/76 个跨相机身份 —— 即**跨相机归并本身是有效的，问题集中在单路相机的重复注册**。

**结论：该底库无法通过归并修复。** 归并候选数实测（阈值 → 候选对数，全部身份对 13,530）：0.68 → 7,493（55.4%）、0.95 → 7,276、0.99 → 7,179、0.999 → 7,171、**1.0 → 6,340**、>1.0 → 0。阈值取 1.0 时仍有 6,340 组候选，说明大量不同身份的中心化特征在数值上相同，**不存在安全阈值**；任何阈值都会把底库并成极少数身份。已在归并脚本中加入候选占比护栏（5%）以阻止误操作。正确路径为重建底库并同时解决重复注册成因，需每臂 ≥30 分钟的长窗口对照实验或跨相机人工标注集。

### 7.2 标定方法的覆盖盲区

自动标注集的正样本全部来自同相机相邻帧，**未包含跨相机同人样本**。因此 §5 的精度指标反映的是同相机条件下的判定能力，跨相机条件下的实际精度尚无直接标定数据。后续若发现跨相机漏配，应优先补充跨相机人工标注正样本。

### 7.3 行人身份信息为空

| 检查项 | 结果 |
|---|---|
| `personnel` 表 | 0 行 |
| `personnel_photos` 表 | 0 行 |
| `identities.person_id` | 全部为 NULL |
| `outputs/personnel_crops/` | 空目录 |

系统当前仅输出自动分配的匿名标识，无任何姓名信息。姓名的两个来源——人工绑定与注册照底库命中——均尚未产生数据。因此当前表述应为"标识 A 出现于某几路视频"，而非"某人出现于某几路视频"。

### 7.4 点位与几何参数未标定

- `camera_map.json` 中 22 条记录的平面图坐标 `map_xy` 全部为空值，朝向与视场角为默认值
- 相机点位对照表基于真实材料编制（监控平面图与点位清单），但尚未完成平面图落点
- 该缺项为轨迹回放面板与行程串联功能的前置条件

## 9. 结论

系统已具备跨摄像头行人身份归一与视频检索能力，核心机制（外观特征 + 公共分量中心化 + 阈值与 Ratio Test 双重判据 + 多帧确认）已在真实数据上完成端到端验证，且检索结果可精确定位至视频内秒级位置。

下一阶段的工作重点为：**提升同一行人的归一稳定性，并完成实名数据与点位标定**，以使"识别出是谁"这一能力具备可演示、可验收的完整闭环。
